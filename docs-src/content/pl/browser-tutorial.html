Samouczek krok po kroku w przeglądarce

Najmniejsza możliwa działająca konfiguracja: baza danych PostgreSQL, PgArachne i jedna prosta strona HTML, która loguje się za pomocą uwierzytelniania HTTP Basic i korzysta z trzech endpointów — JSON-RPC, SSE i pobierania plików. Bez frameworka i bez biblioteki JavaScript.

Pobierz gotowy przykład i śledź kolejne kroki: setup.sql (baza danych) oraz index.html (strona WWW).

1. Wymagania wstępne

  • Działający serwer PostgreSQL i plik binarny pgarachne (zobacz Instalacja).
  • Nowoczesna przeglądarka. Wszystko poniżej działa z wbudowanym fetch() — nie trzeba niczego pobierać.

2. Przygotowanie bazy danych

Sam PgArachne łączy się jako rola serwisowa i ładuje własny schemat pomocniczy. Utwórz oba jednorazowo:

createdb my_database
psql -d my_database -c "CREATE ROLE pgarachne LOGIN PASSWORD 'pgarachne_password'"
psql -d my_database -f sql/schema.sql       # PgArachne helper schema (from the repository)
psql -d my_database -f setup.sql            # the demo role and functions (download above)

setup.sql tworzy rolę logowania webuser (osoba korzystająca ze strony WWW), schemat api i trzy funkcje. Działanie każdej z nich wyjaśniają kroki 5–7.

Uprawnienia stanowią cały model bezpieczeństwa. Użytkownik może wywołać funkcję tylko wtedy, gdy PostgreSQL na to pozwala: USAGE na schemacie i EXECUTE na funkcji. W demo webuser otrzymuje dokładnie te uprawnienia do trzech funkcji — nic więcej nie jest dostępne. PostgreSQL domyślnie nadaje EXECUTE na nowych funkcjach wszystkim; w prawdziwych projektach uruchom ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC i trzymaj udostępniane funkcje w osobnym schemacie (zobacz Bezpieczeństwo i uwierzytelnianie).

3. Konfiguracja i uruchomienie PgArachne

Utwórz pgarachne.env obok pliku binarnego. STATIC_FILES_PATH sprawia, że PgArachne serwuje także stronę WWW, dzięki czemu strona i API mają ten sam origin (konfiguracja CORS nie jest potrzebna):

DB_HOST=localhost
DB_PORT=5432
DB_USER=pgarachne
DB_SSLMODE=disable                 # local, non-TLS PostgreSQL only
STATIC_FILES_PATH=/path/to/folder/with/index.html

Hasło roli serwisowej sterownik PostgreSQL odczytuje z PGPASSWORD (lub ~/.pgpass). JWT_SECRET nie jest potrzebny — ten samouczek używa wyłącznie uwierzytelniania Basic.

PGPASSWORD=pgarachne_password ./pgarachne

Otwórz http://localhost:8080/ po zapisaniu index.html w tym folderze (krok 8). Rola webuser musi mieć możliwość logowania do PostgreSQL z hosta PgArachne (pg_hba.conf z uwierzytelnianiem hasłem).

4. Uwierzytelnianie: HTTP Basic

Przeglądarka wysyła nazwę użytkownika i hasło PostgreSQL z każdym żądaniem; PgArachne otwiera połączenie jako ten użytkownik, więc wszystkie uprawnienia PostgreSQL (oraz Row-Level Security) obowiązują bezpośrednio.

// Authorization header. TextEncoder makes non-ASCII passwords work.
function authHeader(user, pass) {
  const bytes = new TextEncoder().encode(user + ":" + pass);
  return "Basic " + btoa(String.fromCharCode(...bytes));
}
const base = location.origin + "/db/my_database";   // /{API_PREFIX}/{database}

Błędne dane logowania zwracają HTTP 401 z błędem JSON; powtarzane nieudane próby są ograniczane (429).

5. Endpoint 1 — JSON-RPC: wywołanie funkcji

POST /db/{database}/jsonrpc wywołuje schema.function(jsonb). Funkcja przyjmuje jeden argument jsonb i zwraca json.

PostgreSQL (w setup.sql):

CREATE FUNCTION api.greet(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE sql AS $$
  SELECT json_build_object(
    'message', 'Hello, ' || COALESCE(params->>'name', 'world') || '!',
    'database_user', current_user,
    'server_time', now());
$$;
GRANT USAGE ON SCHEMA api TO webuser;
GRANT EXECUTE ON FUNCTION api.greet(jsonb) TO webuser;

Przeglądarka:

async function rpc(method, params) {
  const res = await fetch(base + "/jsonrpc", {
    method: "POST",
    headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", method, params, id: 1 }),
  });
  const body = await res.json();
  if (!res.ok || body.error) throw new Error(body.error.message);
  return body.result;
}

console.log(await rpc("api.greet", { name: "Alice" }));
// { message: "Hello, Alice!", database_user: "webuser", server_time: "..." }

Test za pomocą curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"api.greet","params":{"name":"Alice"},"id":1}' \
  http://localhost:8080/db/my_database/jsonrpc

6. Endpoint 2 — SSE: odbieranie wiadomości w czasie rzeczywistym

GET /db/{database}/sse?channels=demo przesyła wiadomości PostgreSQL NOTIFY jako Server-Sent Events. Każda funkcja może publikować za pomocą pg_notify.

PostgreSQL:

CREATE FUNCTION api.send_message(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_notify('demo', json_build_object('from', current_user, 'text', params->>'text')::text);
  RETURN '{"sent": true}'::json;
END; $$;
GRANT EXECUTE ON FUNCTION api.send_message(jsonb) TO webuser;

Przeglądarka. Wbudowany EventSource nie może wysłać nagłówka Authorization, więc strumień odczytujemy za pomocą fetch():

async function listen(channels, onMessage, signal) {
  const res = await fetch(base + "/sse?channels=" + encodeURIComponent(channels), {
    headers: { "Authorization": authHeader(user, pass) }, signal,
  });
  if (!res.ok) throw new Error((await res.json()).error);
  const reader = res.body.getReader(), decoder = new TextDecoder();
  let buffer = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {      // an event ends with a blank line
      const event = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      for (const line of event.split("\n"))
        if (line.startsWith("data: ")) onMessage(JSON.parse(line.slice(6)));  // ":" lines are heartbeats
    }
  }
}

const controller = new AbortController();           // controller.abort() stops listening
listen("demo", (m) => console.log(m), controller.signal);
await rpc("api.send_message", { text: "Hello" });   // → { channel: "demo", data: { from: "webuser", text: "Hello" } }
Kanały nie są ograniczone rolami: każdy uwierzytelniony użytkownik może subskrybować dowolną nazwę kanału. Nie wysyłaj przez NOTIFY danych, których nie każdy użytkownik może widzieć (szczegóły w Powiadomienia w czasie rzeczywistym).

Test za pomocą curl: curl -N -u webuser:webuser_password "http://localhost:8080/db/my_database/sse?channels=demo", a następnie wywołaj api.send_message z innego terminala.

7. Endpoint 3 — File: pobieranie wygenerowanego pliku

POST /db/{database}/file zwraca surowe bajty (lub ZIP, gdy funkcja zwraca kilka plików) — bez base64 w JSON. Funkcja zwraca wiersze (path, content, mime_type, store_only).

PostgreSQL:

CREATE FUNCTION api.export_report(params jsonb DEFAULT '{}'::jsonb)
RETURNS TABLE (path text, content bytea, mime_type text, store_only boolean)
LANGUAGE sql AS $$
  SELECT 'report.csv', convert_to('id,name' || E'\n' || '1,Alice' || E'\n' || '2,Bob' || E'\n', 'UTF8'),
         'text/csv', false;
$$;
GRANT EXECUTE ON FUNCTION api.export_report(jsonb) TO webuser;

Zwróć więcej wierszy, aby automatycznie otrzymać ZIP. Wszystkie opcje opisano w Pobieranie plików.

Przeglądarka:

const res = await fetch(base + "/file", {
  method: "POST",
  headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
  body: JSON.stringify({ method: "api.export_report", params: {}, options: { filename: "report.csv" } }),
});
if (!res.ok) throw new Error((await res.json()).error.message);   // errors are JSON, never binary
const url = URL.createObjectURL(await res.blob());
const a = Object.assign(document.createElement("a"), { href: url, download: "report.csv" });
document.body.appendChild(a); a.click(); a.remove();
URL.revokeObjectURL(url);

Test za pomocą curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"method":"api.export_report"}' http://localhost:8080/db/my_database/file -OJ

8. Złożenie wszystkiego w całość

Zapisz index.html w folderze STATIC_FILES_PATH i otwórz http://localhost:8080/. Zawiera trzy powyższe fragmenty podpięte do przycisków (~100 linii, bez zależności). Wpisz nazwę bazy danych, zostaw webuser / webuser_password i wypróbuj każdy przycisk: Call api.greet, Start listening, następnie Send oraz Download report.csv.

9. Przejście na produkcję

  • HTTPS: dane logowania Basic są wysyłane z każdym żądaniem — zawsze używaj TLS (zobacz Wdrożenie i HTTPS) i zmień hasło demo.
  • Trzymaj dane logowania wyłącznie w pamięci (w zmiennej), nie w localStorage. Aby tworzyć sesje bez ponownego wysyłania hasła, włącz JWT_SECRET i użyj get_jwt (zobacz Bezpieczeństwo i uwierzytelnianie).
  • Inny origin dla strony WWW (np. CDN lub inny port): ustaw ALLOWED_ORIGINS=https://app.example.com. Żądania cross-origin są domyślnie blokowane.
  • Zasada najmniejszych uprawnień: jedna rola PostgreSQL na rodzaj użytkownika, EXECUTE tylko na potrzebnych funkcjach, Row-Level Security dla danych poszczególnych użytkowników.
