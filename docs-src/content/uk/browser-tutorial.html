Покроковий посібник для браузера

Найменша можлива робоча конфігурація: база даних PostgreSQL, PgArachne і одна проста HTML-сторінка, яка входить через HTTP Basic-автентифікацію та використовує три ендпоінти — JSON-RPC, SSE і завантаження файлів. Без фреймворків і без JavaScript-бібліотек.

Завантажте готовий приклад і робіть усе разом зі мною: setup.sql (база даних) і index.html (вебсторінка).

1. Передумови

  • Запущений сервер PostgreSQL і бінарний файл pgarachne (див. Встановлення).
  • Сучасний браузер. Усе нижче працює з вбудованим fetch() — нічого завантажувати не потрібно.

2. Підготуйте базу даних

Сам PgArachne підключається як сервісна роль і завантажує свою допоміжну схему. Створіть обидві один раз:

createdb my_database
psql -d my_database -c "CREATE ROLE pgarachne LOGIN PASSWORD 'pgarachne_password'"
psql -d my_database -f sql/schema.sql       # PgArachne helper schema (from the repository)
psql -d my_database -f setup.sql            # the demo role and functions (download above)

setup.sql створює роль для входу webuser (користувач вебсторінки), схему api і три функції. Як працює кожна з них, пояснено в кроках 5–7.

Права доступу — це вся модель безпеки. Користувач може викликати функцію лише тоді, коли PostgreSQL це дозволяє: USAGE на схему та EXECUTE на функцію. У демо webuser отримує саме ці права на три функції — більше нічого не доступно. PostgreSQL за замовчуванням надає EXECUTE на нові функції всім; для реальних проєктів виконайте ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC і тримайте відкриті функції в окремій схемі (див. Безпека та автентифікація).

3. Налаштуйте та запустіть PgArachne

Створіть pgarachne.env поруч із бінарним файлом. STATIC_FILES_PATH змушує PgArachne також віддавати вебсторінку, тож сторінка й API мають одне походження (налаштовувати CORS не потрібно):

DB_HOST=localhost
DB_PORT=5432
DB_USER=pgarachne
DB_SSLMODE=disable                 # local, non-TLS PostgreSQL only
STATIC_FILES_PATH=/path/to/folder/with/index.html

Пароль сервісної ролі драйвер PostgreSQL читає з PGPASSWORD (або ~/.pgpass). JWT_SECRET не потрібен — цей посібник використовує лише Basic-автентифікацію.

PGPASSWORD=pgarachne_password ./pgarachne

Відкрийте http://localhost:8080/ після того, як збережете index.html у цю теку (крок 8). Роль webuser має мати змогу входити в PostgreSQL з хоста PgArachne (pg_hba.conf з автентифікацією за паролем).

4. Автентифікація: HTTP Basic

Браузер надсилає ім'я користувача й пароль PostgreSQL з кожним запитом; PgArachne відкриває з'єднання від імені цього користувача, тому всі права PostgreSQL (і Row-Level Security) діють безпосередньо.

// Authorization header. TextEncoder makes non-ASCII passwords work.
function authHeader(user, pass) {
  const bytes = new TextEncoder().encode(user + ":" + pass);
  return "Basic " + btoa(String.fromCharCode(...bytes));
}
const base = location.origin + "/db/my_database";   // /{API_PREFIX}/{database}

Неправильні облікові дані повертають HTTP 401 з JSON-помилкою; повторні невдалі спроби обмежуються (429).

5. Ендпоінт 1 — JSON-RPC: виклик функції

POST /db/{database}/jsonrpc викликає schema.function(jsonb). Функція приймає один аргумент jsonb і повертає json.

PostgreSQL (у setup.sql):

CREATE FUNCTION api.greet(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE sql AS $$
  SELECT json_build_object(
    'message', 'Hello, ' || COALESCE(params->>'name', 'world') || '!',
    'database_user', current_user,
    'server_time', now());
$$;
GRANT USAGE ON SCHEMA api TO webuser;
GRANT EXECUTE ON FUNCTION api.greet(jsonb) TO webuser;

Браузер:

async function rpc(method, params) {
  const res = await fetch(base + "/jsonrpc", {
    method: "POST",
    headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", method, params, id: 1 }),
  });
  const body = await res.json();
  if (!res.ok || body.error) throw new Error(body.error.message);
  return body.result;
}

console.log(await rpc("api.greet", { name: "Alice" }));
// { message: "Hello, Alice!", database_user: "webuser", server_time: "..." }

Перевірка через curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"api.greet","params":{"name":"Alice"},"id":1}' \
  http://localhost:8080/db/my_database/jsonrpc

6. Ендпоінт 2 — SSE: отримання повідомлень у реальному часі

GET /db/{database}/sse?channels=demo передає повідомлення PostgreSQL NOTIFY як Server-Sent Events. Будь-яка функція може публікувати через pg_notify.

PostgreSQL:

CREATE FUNCTION api.send_message(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_notify('demo', json_build_object('from', current_user, 'text', params->>'text')::text);
  RETURN '{"sent": true}'::json;
END; $$;
GRANT EXECUTE ON FUNCTION api.send_message(jsonb) TO webuser;

Браузер. Вбудований EventSource не вміє надсилати заголовок Authorization, тому читайте потік через fetch():

async function listen(channels, onMessage, signal) {
  const res = await fetch(base + "/sse?channels=" + encodeURIComponent(channels), {
    headers: { "Authorization": authHeader(user, pass) }, signal,
  });
  if (!res.ok) throw new Error((await res.json()).error);
  const reader = res.body.getReader(), decoder = new TextDecoder();
  let buffer = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {      // an event ends with a blank line
      const event = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      for (const line of event.split("\n"))
        if (line.startsWith("data: ")) onMessage(JSON.parse(line.slice(6)));  // ":" lines are heartbeats
    }
  }
}

const controller = new AbortController();           // controller.abort() stops listening
listen("demo", (m) => console.log(m), controller.signal);
await rpc("api.send_message", { text: "Hello" });   // → { channel: "demo", data: { from: "webuser", text: "Hello" } }
Канали не обмежені ролями: будь-який автентифікований користувач може підписатися на будь-який канал. Не надсилайте через NOTIFY дані, які можуть бачити не всі користувачі (докладніше в розділі Сповіщення в реальному часі (SSE)).

Перевірка через curl: curl -N -u webuser:webuser_password "http://localhost:8080/db/my_database/sse?channels=demo", потім викличте api.send_message з іншого термінала.

7. Ендпоінт 3 — File: завантаження згенерованого файлу

POST /db/{database}/file повертає сирі байти (або ZIP, якщо функція повертає кілька файлів) — без base64 у JSON. Функція повертає рядки (path, content, mime_type, store_only).

PostgreSQL:

CREATE FUNCTION api.export_report(params jsonb DEFAULT '{}'::jsonb)
RETURNS TABLE (path text, content bytea, mime_type text, store_only boolean)
LANGUAGE sql AS $$
  SELECT 'report.csv', convert_to('id,name' || E'\n' || '1,Alice' || E'\n' || '2,Bob' || E'\n', 'UTF8'),
         'text/csv', false;
$$;
GRANT EXECUTE ON FUNCTION api.export_report(jsonb) TO webuser;

Поверніть більше рядків, щоб автоматично отримати ZIP. Усі параметри дивіться в розділі Завантаження файлів (/file).

Браузер:

const res = await fetch(base + "/file", {
  method: "POST",
  headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
  body: JSON.stringify({ method: "api.export_report", params: {}, options: { filename: "report.csv" } }),
});
if (!res.ok) throw new Error((await res.json()).error.message);   // errors are JSON, never binary
const url = URL.createObjectURL(await res.blob());
const a = Object.assign(document.createElement("a"), { href: url, download: "report.csv" });
document.body.appendChild(a); a.click(); a.remove();
URL.revokeObjectURL(url);

Перевірка через curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"method":"api.export_report"}' http://localhost:8080/db/my_database/file -OJ

8. Зберіть усе разом

Збережіть index.html у теку STATIC_FILES_PATH і відкрийте http://localhost:8080/. Він містить три наведені вище фрагменти, підключені до кнопок (~100 рядків, без залежностей). Введіть назву бази даних, залиште webuser / webuser_password і спробуйте кожну кнопку: Call api.greet, Start listening, потім Send, і Download report.csv.

9. Перехід у продакшн

  • HTTPS: облікові дані Basic передаються з кожним запитом — завжди використовуйте TLS (див. Розгортання та HTTPS) і змініть демо-пароль.
  • Зберігайте облікові дані лише в пам'яті (у змінній), а не в localStorage. Для сесій без повторного надсилання пароля увімкніть JWT_SECRET і використовуйте get_jwt (див. Безпека та автентифікація).
  • Інше походження вебсторінки (наприклад, CDN або інший порт): задайте ALLOWED_ORIGINS=https://app.example.com. Міждоменні запити за замовчуванням заблоковані.
  • Мінімальні привілеї: одна роль PostgreSQL на кожен тип користувачів, EXECUTE лише на потрібні їм функції, Row-Level Security для даних окремих користувачів.
