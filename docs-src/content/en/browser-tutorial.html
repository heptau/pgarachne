Step-by-Step Browser Tutorial

The smallest possible working setup: a PostgreSQL database, PgArachne, and one plain HTML page that logs in with HTTP Basic authentication and uses three endpoints — JSON-RPC, SSE and file download. No framework and no JavaScript library.

Download the finished example and follow along: setup.sql (database) and index.html (web page).

1. Prerequisites

  • A running PostgreSQL server and the pgarachne binary (see Installation).
  • A modern browser. Everything below works with the built-in fetch() — nothing to download.

2. Prepare the database

PgArachne itself connects as a service role and loads its helper schema. Create both once:

createdb my_database
psql -d my_database -c "CREATE ROLE pgarachne LOGIN PASSWORD 'pgarachne_password'"
psql -d my_database -f sql/schema.sql       # PgArachne helper schema (from the repository)
psql -d my_database -f setup.sql            # the demo role and functions (download above)

setup.sql creates a login role webuser (the person using the web page), a schema api and three functions. How each one works is explained in steps 5–7.

Permissions are the whole security model. A user can call a function only if PostgreSQL lets them: USAGE on the schema and EXECUTE on the function. In the demo webuser gets exactly those on three functions — nothing else is reachable. PostgreSQL grants EXECUTE on new functions to everyone by default; for real projects run ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC and keep exposed functions in a dedicated schema (see Security).

3. Configure and start PgArachne

Create pgarachne.env next to the binary. STATIC_FILES_PATH makes PgArachne also serve the web page, so the page and the API share one origin (no CORS setup needed):

DB_HOST=localhost
DB_PORT=5432
DB_USER=pgarachne
DB_SSLMODE=disable                 # local, non-TLS PostgreSQL only
STATIC_FILES_PATH=/path/to/folder/with/index.html

The service role's password is read by the PostgreSQL driver from PGPASSWORD (or ~/.pgpass). JWT_SECRET is not needed — this tutorial uses Basic authentication only.

PGPASSWORD=pgarachne_password ./pgarachne

Open http://localhost:8080/ after you save index.html into that folder (step 8). The role webuser must be allowed to log in to PostgreSQL from the PgArachne host (pg_hba.conf with password authentication).

4. Authentication: HTTP Basic

The browser sends the PostgreSQL user and password with every request; PgArachne opens a connection as that user, so all PostgreSQL permissions (and Row-Level Security) apply directly.

// Authorization header. TextEncoder makes non-ASCII passwords work.
function authHeader(user, pass) {
  const bytes = new TextEncoder().encode(user + ":" + pass);
  return "Basic " + btoa(String.fromCharCode(...bytes));
}
const base = location.origin + "/db/my_database";   // /{API_PREFIX}/{database}

Wrong credentials return HTTP 401 with a JSON error; repeated failures are rate limited (429).

5. Endpoint 1 — JSON-RPC: call a function

POST /db/{database}/jsonrpc calls schema.function(jsonb). The function takes one jsonb argument and returns json.

PostgreSQL (in setup.sql):

CREATE FUNCTION api.greet(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE sql AS $$
  SELECT json_build_object(
    'message', 'Hello, ' || COALESCE(params->>'name', 'world') || '!',
    'database_user', current_user,
    'server_time', now());
$$;
GRANT USAGE ON SCHEMA api TO webuser;
GRANT EXECUTE ON FUNCTION api.greet(jsonb) TO webuser;

Browser:

async function rpc(method, params) {
  const res = await fetch(base + "/jsonrpc", {
    method: "POST",
    headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", method, params, id: 1 }),
  });
  const body = await res.json();
  if (!res.ok || body.error) throw new Error(body.error.message);
  return body.result;
}

console.log(await rpc("api.greet", { name: "Alice" }));
// { message: "Hello, Alice!", database_user: "webuser", server_time: "..." }

Test with curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"api.greet","params":{"name":"Alice"},"id":1}' \
  http://localhost:8080/db/my_database/jsonrpc

6. Endpoint 2 — SSE: receive real-time messages

GET /db/{database}/sse?channels=demo streams PostgreSQL NOTIFY messages as Server-Sent Events. Any function can publish with pg_notify.

PostgreSQL:

CREATE FUNCTION api.send_message(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_notify('demo', json_build_object('from', current_user, 'text', params->>'text')::text);
  RETURN '{"sent": true}'::json;
END; $$;
GRANT EXECUTE ON FUNCTION api.send_message(jsonb) TO webuser;

Browser. The built-in EventSource cannot send an Authorization header, so read the stream with fetch():

async function listen(channels, onMessage, signal) {
  const res = await fetch(base + "/sse?channels=" + encodeURIComponent(channels), {
    headers: { "Authorization": authHeader(user, pass) }, signal,
  });
  if (!res.ok) throw new Error((await res.json()).error);
  const reader = res.body.getReader(), decoder = new TextDecoder();
  let buffer = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {      // an event ends with a blank line
      const event = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      for (const line of event.split("\n"))
        if (line.startsWith("data: ")) onMessage(JSON.parse(line.slice(6)));  // ":" lines are heartbeats
    }
  }
}

const controller = new AbortController();           // controller.abort() stops listening
listen("demo", (m) => console.log(m), controller.signal);
await rpc("api.send_message", { text: "Hello" });   // → { channel: "demo", data: { from: "webuser", text: "Hello" } }
Channels are not role-scoped: any authenticated user can subscribe to any channel name. Do not NOTIFY data that not every user may see (details in Real-time Notifications).

Test with curl: curl -N -u webuser:webuser_password "http://localhost:8080/db/my_database/sse?channels=demo", then call api.send_message from another terminal.

7. Endpoint 3 — File: download a generated file

POST /db/{database}/file returns raw bytes (or a ZIP when the function returns several files) — no base64 in JSON. The function returns rows (path, content, mime_type, store_only).

PostgreSQL:

CREATE FUNCTION api.export_report(params jsonb DEFAULT '{}'::jsonb)
RETURNS TABLE (path text, content bytea, mime_type text, store_only boolean)
LANGUAGE sql AS $$
  SELECT 'report.csv', convert_to('id,name' || E'\n' || '1,Alice' || E'\n' || '2,Bob' || E'\n', 'UTF8'),
         'text/csv', false;
$$;
GRANT EXECUTE ON FUNCTION api.export_report(jsonb) TO webuser;

Return more rows to get a ZIP automatically. See File Download for all options.

Browser:

const res = await fetch(base + "/file", {
  method: "POST",
  headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
  body: JSON.stringify({ method: "api.export_report", params: {}, options: { filename: "report.csv" } }),
});
if (!res.ok) throw new Error((await res.json()).error.message);   // errors are JSON, never binary
const url = URL.createObjectURL(await res.blob());
const a = Object.assign(document.createElement("a"), { href: url, download: "report.csv" });
document.body.appendChild(a); a.click(); a.remove();
URL.revokeObjectURL(url);

Test with curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"method":"api.export_report"}' http://localhost:8080/db/my_database/file -OJ

8. Put it together

Save index.html into the STATIC_FILES_PATH folder and open http://localhost:8080/. It contains the three snippets above wired to buttons (~100 lines, no dependencies). Enter the database name, keep webuser / webuser_password, and try each button: Call api.greet, Start listening then Send, and Download report.csv.

9. Going to production

  • HTTPS: Basic credentials travel with every request — always use TLS (see Deployment & HTTPS) and change the demo password.
  • Keep credentials in memory only (a variable), not in localStorage. For sessions without resending the password, enable JWT_SECRET and use get_jwt (see Security).
  • Different origin for the web page (e.g. a CDN or another port): set ALLOWED_ORIGINS=https://app.example.com. Cross-origin requests are blocked by default.
  • Least privilege: one PostgreSQL role per kind of user, EXECUTE only on the functions they need, Row-Level Security for per-user data.
