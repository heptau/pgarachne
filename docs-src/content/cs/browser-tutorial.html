Návod krok za krokem (prohlížeč)

Nejmenší možné fungující nasazení: databáze PostgreSQL, PgArachne a jedna obyčejná HTML stránka, která se přihlašuje přes HTTP Basic autentizaci a používá tři endpointy — JSON-RPC, SSE a stahování souborů. Bez frameworku a bez JavaScriptové knihovny.

Stáhněte si hotový příklad a postupujte podle návodu: setup.sql (databáze) a index.html (webová stránka).

1. Předpoklady

  • Běžící server PostgreSQL a binárka pgarachne (viz Instalace).
  • Moderní prohlížeč. Vše níže funguje s vestavěným fetch() — není co stahovat.

2. Příprava databáze

PgArachne se k databázi připojuje jako servisní role a potřebuje své pomocné schéma. Obojí vytvořte jednou:

createdb my_database
psql -d my_database -c "CREATE ROLE pgarachne LOGIN PASSWORD 'pgarachne_password'"
psql -d my_database -f sql/schema.sql       # pomocné schéma PgArachne (z repozitáře)
psql -d my_database -f setup.sql            # demo role a funkce (ke stažení výše)

setup.sql vytvoří přihlašovací roli webuser (uživatel webové stránky), schéma api a tři funkce. Jak která funguje, vysvětlují kroky 5–7.

Celý bezpečnostní model tvoří oprávnění. Uživatel smí funkci zavolat jen tehdy, když mu to PostgreSQL dovolí: USAGE na schématu a EXECUTE na funkci. V ukázce má webuser přesně tato práva na třech funkcích — nic dalšího není dostupné. PostgreSQL ve výchozím stavu přidává EXECUTE na nové funkce všem; v reálných projektech spusťte ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC a vystavené funkce držte ve vyhrazeném schématu (viz Bezpečnost a autentizace).

3. Konfigurace a spuštění PgArachne

Vytvořte soubor pgarachne.env vedle binárky. STATIC_FILES_PATH způsobí, že PgArachne servíruje i webovou stránku, takže stránka a API sdílejí jeden origin (není třeba nastavovat CORS):

DB_HOST=localhost
DB_PORT=5432
DB_USER=pgarachne
DB_SSLMODE=disable                 # jen lokální PostgreSQL bez TLS
STATIC_FILES_PATH=/path/to/folder/with/index.html

Heslo servisní role čte databázový ovladač z PGPASSWORD (nebo z ~/.pgpass). JWT_SECRET není potřeba — návod používá jen Basic autentizaci.

PGPASSWORD=pgarachne_password ./pgarachne

Po uložení index.html do této složky (krok 8) otevřete http://localhost:8080/. Role webuser se musí moct přihlásit k PostgreSQL z počítače, kde běží PgArachne (pg_hba.conf s heslovou autentizací).

4. Autentizace: HTTP Basic

Prohlížeč posílá uživatele a heslo do PostgreSQL s každým požadavkem; PgArachne otevře spojení jako tento uživatel, takže přímo platí všechna oprávnění PostgreSQL (i Row-Level Security).

// Hlavička Authorization. TextEncoder zajistí funkčnost hesel s diakritikou.
function authHeader(user, pass) {
  const bytes = new TextEncoder().encode(user + ":" + pass);
  return "Basic " + btoa(String.fromCharCode(...bytes));
}
const base = location.origin + "/db/my_database";   // /{API_PREFIX}/{database}

Špatné přihlašovací údaje vrátí HTTP 401 s JSON chybou; opakované neúspěchy jsou omezeny (429).

5. Endpoint 1 — JSON-RPC: zavolání funkce

POST /db/{database}/jsonrpc zavolá schema.function(jsonb). Funkce přijímá jeden argument typu jsonb a vrací json.

PostgreSQL (v setup.sql):

CREATE FUNCTION api.greet(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE sql AS $$
  SELECT json_build_object(
    'message', 'Hello, ' || COALESCE(params->>'name', 'world') || '!',
    'database_user', current_user,
    'server_time', now());
$$;
GRANT USAGE ON SCHEMA api TO webuser;
GRANT EXECUTE ON FUNCTION api.greet(jsonb) TO webuser;

Prohlížeč:

async function rpc(method, params) {
  const res = await fetch(base + "/jsonrpc", {
    method: "POST",
    headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", method, params, id: 1 }),
  });
  const body = await res.json();
  if (!res.ok || body.error) throw new Error(body.error.message);
  return body.result;
}

console.log(await rpc("api.greet", { name: "Alice" }));
// { message: "Hello, Alice!", database_user: "webuser", server_time: "..." }

Test pomocí curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"api.greet","params":{"name":"Alice"},"id":1}' \
  http://localhost:8080/db/my_database/jsonrpc

6. Endpoint 2 — SSE: příjem zpráv v reálném čase

GET /db/{database}/sse?channels=demo streamuje zprávy PostgreSQL NOTIFY jako Server-Sent Events. Publikovat může libovolná funkce přes pg_notify.

PostgreSQL:

CREATE FUNCTION api.send_message(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_notify('demo', json_build_object('from', current_user, 'text', params->>'text')::text);
  RETURN '{"sent": true}'::json;
END; $$;
GRANT EXECUTE ON FUNCTION api.send_message(jsonb) TO webuser;

Prohlížeč. Vestavěný EventSource neumí poslat hlavičku Authorization, proto stream čteme pomocí fetch():

async function listen(channels, onMessage, signal) {
  const res = await fetch(base + "/sse?channels=" + encodeURIComponent(channels), {
    headers: { "Authorization": authHeader(user, pass) }, signal,
  });
  if (!res.ok) throw new Error((await res.json()).error);
  const reader = res.body.getReader(), decoder = new TextDecoder();
  let buffer = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {      // událost končí prázdným řádkem
      const event = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      for (const line of event.split("\n"))
        if (line.startsWith("data: ")) onMessage(JSON.parse(line.slice(6)));  // řádky začínající ":" jsou heartbeat
    }
  }
}

const controller = new AbortController();           // controller.abort() ukončí naslouchání
listen("demo", (m) => console.log(m), controller.signal);
await rpc("api.send_message", { text: "Hello" });   // → { channel: "demo", data: { from: "webuser", text: "Hello" } }
Kanály nejsou vázané na role: každý přihlášený uživatel může odebírat libovolný kanál. Neposílejte přes NOTIFY data, která nesmí vidět každý (podrobnosti v Real-time notifikace (SSE)).

Test pomocí curl: curl -N -u webuser:webuser_password "http://localhost:8080/db/my_database/sse?channels=demo", poté z jiného terminálu zavolejte api.send_message.

7. Endpoint 3 — File: stažení vygenerovaného souboru

POST /db/{database}/file vrací surová data (nebo ZIP, pokud funkce vrátí víc souborů) — žádné base64 v JSON. Funkce vrací řádky (path, content, mime_type, store_only).

PostgreSQL:

CREATE FUNCTION api.export_report(params jsonb DEFAULT '{}'::jsonb)
RETURNS TABLE (path text, content bytea, mime_type text, store_only boolean)
LANGUAGE sql AS $$
  SELECT 'report.csv', convert_to('id,name' || E'\n' || '1,Alice' || E'\n' || '2,Bob' || E'\n', 'UTF8'),
         'text/csv', false;
$$;
GRANT EXECUTE ON FUNCTION api.export_report(jsonb) TO webuser;

Vrátíte-li víc řádků, vznikne automaticky ZIP. Všechny volby viz Stahování souborů.

Prohlížeč:

const res = await fetch(base + "/file", {
  method: "POST",
  headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
  body: JSON.stringify({ method: "api.export_report", params: {}, options: { filename: "report.csv" } }),
});
if (!res.ok) throw new Error((await res.json()).error.message);   // chyby jsou JSON, nikdy binární data
const url = URL.createObjectURL(await res.blob());
const a = Object.assign(document.createElement("a"), { href: url, download: "report.csv" });
document.body.appendChild(a); a.click(); a.remove();
URL.revokeObjectURL(url);

Test pomocí curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"method":"api.export_report"}' http://localhost:8080/db/my_database/file -OJ

8. Složení dohromady

Uložte index.html do složky STATIC_FILES_PATH a otevřete http://localhost:8080/. Obsahuje tři výše uvedené ukázky napojené na tlačítka (~100 řádků, žádné závislosti). Zadejte název databáze, ponechte webuser / webuser_password a vyzkoušejte každé tlačítko: Call api.greet, Start listening a pak Send, a Download report.csv.

9. Přechod do produkce

  • HTTPS: Basic údaje putují s každým požadavkem — vždy používejte TLS (viz Nasazení a HTTPS) a změňte heslo z ukázky.
  • Přihlašovací údaje držte jen v paměti (proměnná), ne v localStorage. Pro relace bez opakovaného posílání hesla zapněte JWT_SECRET a použijte get_jwt (viz Bezpečnost a autentizace).
  • Jiný origin webové stránky (např. CDN nebo jiný port): nastavte ALLOWED_ORIGINS=https://app.example.com. Cross-origin požadavky jsou ve výchozím stavu blokované.
  • Nejmenší oprávnění: jedna role PostgreSQL pro každý typ uživatele, EXECUTE jen na potřebné funkce, Row-Level Security pro data jednotlivých uživatelů.
