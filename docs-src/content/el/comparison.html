Σύγκριση: PgArachne έναντι PostgREST

Χαρακτηριστικό PgArachne (+ Universal Functions) PostgREST
Ταχύτητα Εγκατάστασης Υψηλή. Οι universal functions επιτρέπουν άμεσο CRUD, όμοιο με το PostgREST. Υψηλή. Δημιουργεί αυτόματα endpoints για όλους τους πίνακες.
Ευελιξία Λογικής Απεριόριστη. Δυνατότητα συνδυασμού universal CRUD με ειδικές RPC functions. Περιορισμένη. Η περισσότερη λογική πρέπει να βρίσκεται σε URL filters ή Database Views.
Χειρισμός Σχήματος Native. Πρόσβαση μέσω schema.function. Flat/Global. Απαιτεί αλλαγή προφίλ σε HTTP headers για αλλαγή σχήματος.
Abstraction Προαιρετικό. Μπορείτε είτε να εκθέσετε δεδομένα απευθείας (proxy) είτε να τα ενσωματώσετε με ασφάλεια. Χαμηλό. Το API είναι ουσιαστικά ένας καθρέφτης του σχήματος της βάσης δεδομένων.
Έτοιμο για AI & LLM Εξαιρετικό. JSON-RPC και δυνατότητα ορισμού functions «Tool» ειδικά για AI agents. Μέτριο. Το AI πρέπει να παλέψει με αυστηρή σύνταξη URL parameters.
Στατικά Αρχεία Ναι. Εξυπηρετεί HTML/JS/CSS απευθείας από ένα μόνο binary. Όχι. Πρέπει να ρυθμίσετε και να διαχειριστείτε ένα εξωτερικό Nginx μπροστά του.
Πραγματικός Χρόνος (SSE) Ναι. Ενσωματωμένο endpoint SSE για streams NOTIFY της PostgreSQL. Όχι. Απαιτεί προσαρμοσμένη διασύνδεση (π.χ. LISTEN/NOTIFY + ξεχωριστή υπηρεσία).
Υποστήριξη Πολλαπλών Βάσεων Δεδομένων Σε επίπεδο server (N:1). Ένα μόνο instance PgArachne συνδέεται στον server (IP:Port) και μπορεί να εξυπηρετήσει όλες τις βάσεις δεδομένων που φιλοξενούνται εκεί. Ανά Βάση Δεδομένων (1:1). Ένα instance είναι δεσμευμένο σε μία συγκεκριμένη βάση δεδομένων. Η εξυπηρέτηση πολλαπλών βάσεων δεδομένων απαιτεί την εκτέλεση πολλαπλών instances σε διαφορετικές θύρες.
Authentication JWT / API Tokens. Υποστηρίζει native και τα δύο. Κυρίως JWT.
Rate Limiting Ναι. Ενσωματωμένο rate limiting για logins (ρυθμιζόμενο). Όχι. Απαιτεί εξωτερικό proxy ή middleware.

Γιατί Νικά το «Υβριδικό PgArachne»

Χάρη στις Universal Functions (που λειτουργούν ως emulator), αποκτάτε το καλύτερο από τους δύο κόσμους:

  • Φάση Εκκίνησης (MVP): Αναπτύξτε το PgArachne με λίγες proxy functions (όπως αυτές στο universal_table_access.sql) και μέσα σε λίγα λεπτά έχετε ένα λειτουργικό API για όλους τους πίνακες. Σε αυτό το στάδιο, συμπεριφέρεται ακριβώς όπως το PostgREST.
  • Φάση Παραγωγής: Καθώς η εφαρμογή μεγαλώνει, ξεκινήστε να γράφετε αποκλειστικές functions για ευαίσθητες λειτουργίες (π.χ. process_payment). Αυτό αυξάνει την ασφάλεια και την απόδοση χωρίς να αλλάξει το υποκείμενο technology stack.
  • Frontend & AI: Ταυτόχρονα, η εφαρμογή σας τρέχει στην ίδια θύρα με το API (χάρη στην εξυπηρέτηση static files), και οι AI agents μπορούν να καλέσουν τις functions σας απευθείας μέσω JSON-RPC.

Σημείωση: Οι «Universal Functions» είναι ένα σύνολο τυπικών PL/pgSQL functions που μπορείτε να προσθέσετε στη βάση δεδομένων σας για να ενεργοποιήσετε γενικές λειτουργίες Read, Create, Update και Delete σε οποιονδήποτε πίνακα.
