Hello World Beispiel

Erstellen wir einen einfachen API-Endpunkt, der einem Benutzer zugeordnet ist.

1. Benutzer und Funktion erstellen

In Ihrer Datenbank (my_database):

-- 1. Benutzer erstellen, der sich bei der API anmelden kann
CREATE ROLE demo_user WITH LOGIN PASSWORD 'user_password';
GRANT USAGE ON SCHEMA api TO demo_user;

-- 2. Hello-World-Funktion erstellen
-- Eingabe: leeres jsonb, Ausgabe: json
CREATE OR REPLACE FUNCTION api.hello_world(payload jsonb)
RETURNS json
LANGUAGE sql
AS $$
    SELECT '"Hello World"'::json;
$$;

-- 3. Berechtigung für den Benutzer vergeben
GRANT EXECUTE ON FUNCTION api.hello_world(jsonb) TO demo_user;

Welche Authentifizierungsmethode soll ich wählen?

  • Option A — JWT-Token: Empfohlen für Produktionsanwendungen und externe Clients. Erfordert einen zusätzlichen Login-Schritt sowie GRANT demo_user TO pgarachne.
  • Option B — Direkte Zugangsdaten: Ideal für Entwicklung, Skripte und interne Dienste. Kein GRANT erforderlich, sofort einsatzbereit.

Weitere Details finden Sie unter Sicherheit & Authentifizierung.

Option A: JWT-Token-Ablauf

A1. Proxy-Privileg erteilen

Damit PgArachne die Rolle wechseln kann, ist ein zusätzliches GRANT erforderlich:

-- PgArachne (Systembenutzer) darf zu demo_user wechseln
GRANT demo_user TO pgarachne;

A2. JWT-Token abrufen

Verwenden Sie die JSON-RPC-Methode get_jwt, um ein JWT-Token zu erhalten:

curl -X POST http://localhost:8080/db/my_database/jsonrpc \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"get_jwt","params":{"login":"demo_user","password":"user_password"},"id":1}'

Antwort:

{"jsonrpc":"2.0","result":{"token":"eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."},"id":1}

A3. Funktion aufrufen

Verwenden Sie das Token, um die Funktion hello_world aufzurufen:

export TOKEN="IHR_JWT_TOKEN_HIER"

curl -X POST http://localhost:8080/db/my_database/jsonrpc \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc": "2.0", "method": "api.hello_world", "params": {}, "id": 1}'

Antwort:

{"jsonrpc": "2.0", "result": "Hello World", "id": 1}

Option B: Direkte Zugangsdaten

Kein GRANT und kein vorheriger Login-Schritt erforderlich. Übergeben Sie den Benutzernamen und das Passwort direkt mit dem -u-Flag von curl:

curl -u demo_user:user_password \
  -X POST http://localhost:8080/db/my_database/jsonrpc \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc": "2.0", "method": "api.hello_world", "params": {}, "id": 1}'

Antwort:

{"jsonrpc": "2.0", "result": "Hello World", "id": 1}

PgArachne verbindet sich direkt als demo_user — es wird kein SET LOCAL ROLE ausgeführt und kein GRANT demo_user TO pgarachne benötigt. Weitere Informationen finden Sie unter Sicherheit & Authentifizierung.
