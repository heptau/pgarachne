Tutorial passo passo nel browser

La configurazione funzionante più piccola possibile: un database PostgreSQL, PgArachne e una semplice pagina HTML che effettua il login con l’autenticazione HTTP Basic e usa tre endpoint — JSON-RPC, SSE e il download di file. Nessun framework e nessuna libreria JavaScript.

Scarica l’esempio completo e segui la guida: setup.sql (database) e index.html (pagina web).

1. Prerequisiti

  • Un server PostgreSQL in esecuzione e il binario pgarachne (vedi Installazione).
  • Un browser moderno. Tutto ciò che segue funziona con il fetch() integrato — non c’è nulla da scaricare.

2. Preparare il database

PgArachne si connette come ruolo di servizio e carica il proprio schema di supporto. Crea entrambi una sola volta:

createdb my_database
psql -d my_database -c "CREATE ROLE pgarachne LOGIN PASSWORD 'pgarachne_password'"
psql -d my_database -f sql/schema.sql       # PgArachne helper schema (from the repository)
psql -d my_database -f setup.sql            # the demo role and functions (download above)

setup.sql crea un ruolo di login webuser (la persona che usa la pagina web), uno schema api e tre funzioni. Il funzionamento di ciascuna è spiegato nei passi 5–7.

I permessi sono l’intero modello di sicurezza. Un utente può chiamare una funzione solo se PostgreSQL lo consente: USAGE sullo schema ed EXECUTE sulla funzione. Nella demo webuser ottiene esattamente questi permessi su tre funzioni — nient’altro è raggiungibile. PostgreSQL concede per impostazione predefinita EXECUTE sulle nuove funzioni a tutti; nei progetti reali esegui ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC e tieni le funzioni esposte in uno schema dedicato (vedi Sicurezza e Autenticazione).

3. Configurare e avviare PgArachne

Crea pgarachne.env accanto al binario. STATIC_FILES_PATH fa sì che PgArachne serva anche la pagina web, in modo che pagina e API condividano la stessa origine (nessuna configurazione CORS necessaria):

DB_HOST=localhost
DB_PORT=5432
DB_USER=pgarachne
DB_SSLMODE=disable                 # local, non-TLS PostgreSQL only
STATIC_FILES_PATH=/path/to/folder/with/index.html

La password del ruolo di servizio viene letta dal driver PostgreSQL da PGPASSWORD (o da ~/.pgpass). JWT_SECRET non è necessario — questo tutorial usa solo l’autenticazione Basic.

PGPASSWORD=pgarachne_password ./pgarachne

Apri http://localhost:8080/ dopo aver salvato index.html in quella cartella (passo 8). Il ruolo webuser deve poter accedere a PostgreSQL dall’host di PgArachne (pg_hba.conf con autenticazione tramite password).

4. Autenticazione: HTTP Basic

Il browser invia utente e password PostgreSQL a ogni richiesta; PgArachne apre una connessione come quell’utente, quindi tutti i permessi PostgreSQL (e la Row-Level Security) si applicano direttamente.

// Authorization header. TextEncoder makes non-ASCII passwords work.
function authHeader(user, pass) {
  const bytes = new TextEncoder().encode(user + ":" + pass);
  return "Basic " + btoa(String.fromCharCode(...bytes));
}
const base = location.origin + "/db/my_database";   // /{API_PREFIX}/{database}

Credenziali errate restituiscono HTTP 401 con un errore JSON; i tentativi falliti ripetuti sono limitati (429).

5. Endpoint 1 — JSON-RPC: chiamare una funzione

POST /db/{database}/jsonrpc chiama schema.function(jsonb). La funzione accetta un solo argomento jsonb e restituisce json.

PostgreSQL (in setup.sql):

CREATE FUNCTION api.greet(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE sql AS $$
  SELECT json_build_object(
    'message', 'Hello, ' || COALESCE(params->>'name', 'world') || '!',
    'database_user', current_user,
    'server_time', now());
$$;
GRANT USAGE ON SCHEMA api TO webuser;
GRANT EXECUTE ON FUNCTION api.greet(jsonb) TO webuser;

Browser:

async function rpc(method, params) {
  const res = await fetch(base + "/jsonrpc", {
    method: "POST",
    headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", method, params, id: 1 }),
  });
  const body = await res.json();
  if (!res.ok || body.error) throw new Error(body.error.message);
  return body.result;
}

console.log(await rpc("api.greet", { name: "Alice" }));
// { message: "Hello, Alice!", database_user: "webuser", server_time: "..." }

Test con curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"api.greet","params":{"name":"Alice"},"id":1}' \
  http://localhost:8080/db/my_database/jsonrpc

6. Endpoint 2 — SSE: ricevere messaggi in tempo reale

GET /db/{database}/sse?channels=demo trasmette i messaggi PostgreSQL NOTIFY come Server-Sent Events. Qualsiasi funzione può pubblicare con pg_notify.

PostgreSQL:

CREATE FUNCTION api.send_message(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_notify('demo', json_build_object('from', current_user, 'text', params->>'text')::text);
  RETURN '{"sent": true}'::json;
END; $$;
GRANT EXECUTE ON FUNCTION api.send_message(jsonb) TO webuser;

Browser. L’EventSource integrato non può inviare un header Authorization, quindi leggi lo stream con fetch():

async function listen(channels, onMessage, signal) {
  const res = await fetch(base + "/sse?channels=" + encodeURIComponent(channels), {
    headers: { "Authorization": authHeader(user, pass) }, signal,
  });
  if (!res.ok) throw new Error((await res.json()).error);
  const reader = res.body.getReader(), decoder = new TextDecoder();
  let buffer = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {      // an event ends with a blank line
      const event = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      for (const line of event.split("\n"))
        if (line.startsWith("data: ")) onMessage(JSON.parse(line.slice(6)));  // ":" lines are heartbeats
    }
  }
}

const controller = new AbortController();           // controller.abort() stops listening
listen("demo", (m) => console.log(m), controller.signal);
await rpc("api.send_message", { text: "Hello" });   // → { channel: "demo", data: { from: "webuser", text: "Hello" } }
I canali non sono limitati per ruolo: qualsiasi utente autenticato può sottoscrivere qualsiasi nome di canale. Non inviare con NOTIFY dati che non tutti gli utenti possono vedere (dettagli in Notifiche in tempo reale).

Test con curl: curl -N -u webuser:webuser_password "http://localhost:8080/db/my_database/sse?channels=demo", poi chiama api.send_message da un altro terminale.

7. Endpoint 3 — File: scaricare un file generato

POST /db/{database}/file restituisce byte grezzi (o uno ZIP quando la funzione restituisce più file) — senza base64 in JSON. La funzione restituisce righe (path, content, mime_type, store_only).

PostgreSQL:

CREATE FUNCTION api.export_report(params jsonb DEFAULT '{}'::jsonb)
RETURNS TABLE (path text, content bytea, mime_type text, store_only boolean)
LANGUAGE sql AS $$
  SELECT 'report.csv', convert_to('id,name' || E'\n' || '1,Alice' || E'\n' || '2,Bob' || E'\n', 'UTF8'),
         'text/csv', false;
$$;
GRANT EXECUTE ON FUNCTION api.export_report(jsonb) TO webuser;

Restituisci più righe per ottenere automaticamente uno ZIP. Vedi Download di file per tutte le opzioni.

Browser:

const res = await fetch(base + "/file", {
  method: "POST",
  headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
  body: JSON.stringify({ method: "api.export_report", params: {}, options: { filename: "report.csv" } }),
});
if (!res.ok) throw new Error((await res.json()).error.message);   // errors are JSON, never binary
const url = URL.createObjectURL(await res.blob());
const a = Object.assign(document.createElement("a"), { href: url, download: "report.csv" });
document.body.appendChild(a); a.click(); a.remove();
URL.revokeObjectURL(url);

Test con curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"method":"api.export_report"}' http://localhost:8080/db/my_database/file -OJ

8. Mettere tutto insieme

Salva index.html nella cartella STATIC_FILES_PATH e apri http://localhost:8080/. Contiene i tre frammenti sopra collegati ai pulsanti (~100 righe, nessuna dipendenza). Inserisci il nome del database, mantieni webuser / webuser_password e prova ogni pulsante: Call api.greet, Start listening poi Send, e Download report.csv.

9. Passare in produzione

  • HTTPS: le credenziali Basic viaggiano con ogni richiesta — usa sempre TLS (vedi Deployment e HTTPS) e cambia la password della demo.
  • Tieni le credenziali solo in memoria (in una variabile), non in localStorage. Per sessioni senza reinvio della password, abilita JWT_SECRET e usa get_jwt (vedi Sicurezza e Autenticazione).
  • Origine diversa per la pagina web (ad es. una CDN o un’altra porta): imposta ALLOWED_ORIGINS=https://app.example.com. Le richieste cross-origin sono bloccate per impostazione predefinita.
  • Privilegio minimo: un ruolo PostgreSQL per tipo di utente, EXECUTE solo sulle funzioni necessarie, Row-Level Security per i dati per utente.
