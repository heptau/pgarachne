Tutorial paso a paso para el navegador

La configuración funcional más pequeña posible: una base de datos PostgreSQL, PgArachne y una sola página HTML sencilla que inicia sesión con autenticación HTTP Basic y usa tres endpoints — JSON-RPC, SSE y descarga de archivos. Sin framework y sin ninguna biblioteca de JavaScript.

Descargue el ejemplo terminado y sígalo paso a paso: setup.sql (base de datos) y index.html (página web).

1. Requisitos previos

  • Un servidor PostgreSQL en ejecución y el binario pgarachne (consulte Instalación).
  • Un navegador moderno. Todo lo que sigue funciona con el fetch() integrado — no hay nada que descargar.

2. Preparar la base de datos

PgArachne se conecta como un rol de servicio y carga su esquema auxiliar. Cree ambos una sola vez:

createdb my_database
psql -d my_database -c "CREATE ROLE pgarachne LOGIN PASSWORD 'pgarachne_password'"
psql -d my_database -f sql/schema.sql       # PgArachne helper schema (from the repository)
psql -d my_database -f setup.sql            # the demo role and functions (download above)

setup.sql crea un rol de inicio de sesión webuser (la persona que usa la página web), un esquema api y tres funciones. Cómo funciona cada una se explica en los pasos 5–7.

Los permisos son todo el modelo de seguridad. Un usuario solo puede llamar a una función si PostgreSQL se lo permite: USAGE sobre el esquema y EXECUTE sobre la función. En la demo, webuser recibe exactamente esos permisos sobre tres funciones — nada más es accesible. PostgreSQL concede EXECUTE sobre las funciones nuevas a todos por defecto; en proyectos reales ejecute ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC y mantenga las funciones expuestas en un esquema dedicado (consulte Seguridad y Autenticación).

3. Configurar e iniciar PgArachne

Cree pgarachne.env junto al binario. STATIC_FILES_PATH hace que PgArachne sirva también la página web, de modo que la página y la API comparten un mismo origen (no hace falta configurar CORS):

DB_HOST=localhost
DB_PORT=5432
DB_USER=pgarachne
DB_SSLMODE=disable                 # local, non-TLS PostgreSQL only
STATIC_FILES_PATH=/path/to/folder/with/index.html

El controlador de PostgreSQL lee la contraseña del rol de servicio desde PGPASSWORD (o ~/.pgpass). JWT_SECRET no es necesario — este tutorial usa únicamente autenticación Basic.

PGPASSWORD=pgarachne_password ./pgarachne

Abra http://localhost:8080/ después de guardar index.html en esa carpeta (paso 8). El rol webuser debe poder iniciar sesión en PostgreSQL desde el host de PgArachne (pg_hba.conf con autenticación por contraseña).

4. Autenticación: HTTP Basic

El navegador envía el usuario y la contraseña de PostgreSQL con cada solicitud; PgArachne abre una conexión como ese usuario, por lo que todos los permisos de PostgreSQL (y la Row-Level Security) se aplican directamente.

// Authorization header. TextEncoder makes non-ASCII passwords work.
function authHeader(user, pass) {
  const bytes = new TextEncoder().encode(user + ":" + pass);
  return "Basic " + btoa(String.fromCharCode(...bytes));
}
const base = location.origin + "/db/my_database";   // /{API_PREFIX}/{database}

Las credenciales incorrectas devuelven HTTP 401 con un error JSON; los fallos repetidos se limitan por tasa (429).

5. Endpoint 1 — JSON-RPC: llamar a una función

POST /db/{database}/jsonrpc llama a schema.function(jsonb). La función recibe un único argumento jsonb y devuelve json.

PostgreSQL (en setup.sql):

CREATE FUNCTION api.greet(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE sql AS $$
  SELECT json_build_object(
    'message', 'Hello, ' || COALESCE(params->>'name', 'world') || '!',
    'database_user', current_user,
    'server_time', now());
$$;
GRANT USAGE ON SCHEMA api TO webuser;
GRANT EXECUTE ON FUNCTION api.greet(jsonb) TO webuser;

Navegador:

async function rpc(method, params) {
  const res = await fetch(base + "/jsonrpc", {
    method: "POST",
    headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", method, params, id: 1 }),
  });
  const body = await res.json();
  if (!res.ok || body.error) throw new Error(body.error.message);
  return body.result;
}

console.log(await rpc("api.greet", { name: "Alice" }));
// { message: "Hello, Alice!", database_user: "webuser", server_time: "..." }

Prueba con curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"api.greet","params":{"name":"Alice"},"id":1}' \
  http://localhost:8080/db/my_database/jsonrpc

6. Endpoint 2 — SSE: recibir mensajes en tiempo real

GET /db/{database}/sse?channels=demo transmite los mensajes NOTIFY de PostgreSQL como Server-Sent Events. Cualquier función puede publicar con pg_notify.

PostgreSQL:

CREATE FUNCTION api.send_message(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_notify('demo', json_build_object('from', current_user, 'text', params->>'text')::text);
  RETURN '{"sent": true}'::json;
END; $$;
GRANT EXECUTE ON FUNCTION api.send_message(jsonb) TO webuser;

Navegador. El EventSource integrado no puede enviar una cabecera Authorization, así que lea el flujo con fetch():

async function listen(channels, onMessage, signal) {
  const res = await fetch(base + "/sse?channels=" + encodeURIComponent(channels), {
    headers: { "Authorization": authHeader(user, pass) }, signal,
  });
  if (!res.ok) throw new Error((await res.json()).error);
  const reader = res.body.getReader(), decoder = new TextDecoder();
  let buffer = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {      // an event ends with a blank line
      const event = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      for (const line of event.split("\n"))
        if (line.startsWith("data: ")) onMessage(JSON.parse(line.slice(6)));  // ":" lines are heartbeats
    }
  }
}

const controller = new AbortController();           // controller.abort() stops listening
listen("demo", (m) => console.log(m), controller.signal);
await rpc("api.send_message", { text: "Hello" });   // → { channel: "demo", data: { from: "webuser", text: "Hello" } }
Los canales no están limitados por rol: cualquier usuario autenticado puede suscribirse a cualquier nombre de canal. No envíe con NOTIFY datos que no todos los usuarios deban ver (detalles en Notificaciones en tiempo real (SSE)).

Prueba con curl: curl -N -u webuser:webuser_password "http://localhost:8080/db/my_database/sse?channels=demo", y luego llame a api.send_message desde otra terminal.

7. Endpoint 3 — Archivo: descargar un archivo generado

POST /db/{database}/file devuelve bytes sin procesar (o un ZIP cuando la función devuelve varios archivos) — sin base64 dentro de JSON. La función devuelve filas (path, content, mime_type, store_only).

PostgreSQL:

CREATE FUNCTION api.export_report(params jsonb DEFAULT '{}'::jsonb)
RETURNS TABLE (path text, content bytea, mime_type text, store_only boolean)
LANGUAGE sql AS $$
  SELECT 'report.csv', convert_to('id,name' || E'\n' || '1,Alice' || E'\n' || '2,Bob' || E'\n', 'UTF8'),
         'text/csv', false;
$$;
GRANT EXECUTE ON FUNCTION api.export_report(jsonb) TO webuser;

Devuelva más filas para obtener un ZIP automáticamente. Consulte Descarga de archivos (/file) para ver todas las opciones.

Navegador:

const res = await fetch(base + "/file", {
  method: "POST",
  headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
  body: JSON.stringify({ method: "api.export_report", params: {}, options: { filename: "report.csv" } }),
});
if (!res.ok) throw new Error((await res.json()).error.message);   // errors are JSON, never binary
const url = URL.createObjectURL(await res.blob());
const a = Object.assign(document.createElement("a"), { href: url, download: "report.csv" });
document.body.appendChild(a); a.click(); a.remove();
URL.revokeObjectURL(url);

Prueba con curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"method":"api.export_report"}' http://localhost:8080/db/my_database/file -OJ

8. Juntarlo todo

Guarde index.html en la carpeta STATIC_FILES_PATH y abra http://localhost:8080/. Contiene los tres fragmentos anteriores conectados a botones (~100 líneas, sin dependencias). Introduzca el nombre de la base de datos, mantenga webuser / webuser_password y pruebe cada botón: Call api.greet, Start listening y luego Send, y Download report.csv.

9. Pasar a producción

  • HTTPS: las credenciales Basic viajan con cada solicitud — use siempre TLS (consulte Despliegue y HTTPS) y cambie la contraseña de la demo.
  • Mantenga las credenciales solo en memoria (una variable), no en localStorage. Para sesiones sin reenviar la contraseña, active JWT_SECRET y use get_jwt (consulte Seguridad y Autenticación).
  • Origen distinto para la página web (p. ej. una CDN u otro puerto): establezca ALLOWED_ORIGINS=https://app.example.com. Las solicitudes cross-origin están bloqueadas por defecto.
  • Mínimo privilegio: un rol de PostgreSQL por tipo de usuario, EXECUTE solo sobre las funciones que necesiten, Row-Level Security para los datos por usuario.
