Οδηγός βήμα προς βήμα για τον περιηγητή

Η μικρότερη δυνατή λειτουργική εγκατάσταση: μια βάση δεδομένων PostgreSQL, το PgArachne και μία απλή σελίδα HTML που συνδέεται με HTTP Basic authentication και χρησιμοποιεί τρία endpoints — JSON-RPC, SSE και λήψη αρχείων. Χωρίς framework και χωρίς βιβλιοθήκη JavaScript.

Κατεβάστε το έτοιμο παράδειγμα και ακολουθήστε τα βήματα: setup.sql (βάση δεδομένων) και index.html (ιστοσελίδα).

1. Προαπαιτούμενα

  • Ένας διακομιστής PostgreSQL σε λειτουργία και το εκτελέσιμο pgarachne (βλ. Εγκατάσταση).
  • Ένας σύγχρονος περιηγητής. Όλα παρακάτω λειτουργούν με το ενσωματωμένο fetch() — δεν χρειάζεται να κατεβάσετε τίποτα.

2. Προετοιμάστε τη βάση δεδομένων

Το ίδιο το PgArachne συνδέεται ως ρόλος υπηρεσίας και φορτώνει το βοηθητικό του σχήμα. Δημιουργήστε και τα δύο μία φορά:

createdb my_database
psql -d my_database -c "CREATE ROLE pgarachne LOGIN PASSWORD 'pgarachne_password'"
psql -d my_database -f sql/schema.sql       # PgArachne helper schema (from the repository)
psql -d my_database -f setup.sql            # the demo role and functions (download above)

Το setup.sql δημιουργεί έναν ρόλο σύνδεσης webuser (το άτομο που χρησιμοποιεί την ιστοσελίδα), ένα σχήμα api και τρεις συναρτήσεις. Πώς λειτουργεί η καθεμία εξηγείται στα βήματα 5–7.

Τα δικαιώματα είναι ολόκληρο το μοντέλο ασφάλειας. Ένας χρήστης μπορεί να καλέσει μια συνάρτηση μόνο αν το επιτρέπει η PostgreSQL: USAGE στο σχήμα και EXECUTE στη συνάρτηση. Στο demo ο webuser παίρνει ακριβώς αυτά σε τρεις συναρτήσεις — τίποτα άλλο δεν είναι προσβάσιμο. Η PostgreSQL δίνει από προεπιλογή EXECUTE στις νέες συναρτήσεις σε όλους· σε πραγματικά έργα εκτελέστε ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC και κρατήστε τις εκτεθειμένες συναρτήσεις σε ξεχωριστό σχήμα (βλ. Ασφάλεια & Πιστοποίηση).

3. Ρυθμίστε και ξεκινήστε το PgArachne

Δημιουργήστε το pgarachne.env δίπλα στο εκτελέσιμο. Το STATIC_FILES_PATH κάνει το PgArachne να σερβίρει και την ιστοσελίδα, ώστε η σελίδα και το API να έχουν την ίδια προέλευση (δεν χρειάζεται ρύθμιση CORS):

DB_HOST=localhost
DB_PORT=5432
DB_USER=pgarachne
DB_SSLMODE=disable                 # local, non-TLS PostgreSQL only
STATIC_FILES_PATH=/path/to/folder/with/index.html

Ο κωδικός του ρόλου υπηρεσίας διαβάζεται από τον οδηγό της PostgreSQL από το PGPASSWORD (ή το ~/.pgpass). Το JWT_SECRET δεν χρειάζεται — αυτός ο οδηγός χρησιμοποιεί μόνο Basic authentication.

PGPASSWORD=pgarachne_password ./pgarachne

Ανοίξτε το http://localhost:8080/ αφού αποθηκεύσετε το index.html σε αυτόν τον φάκελο (βήμα 8). Ο ρόλος webuser πρέπει να επιτρέπεται να συνδέεται στην PostgreSQL από τον host του PgArachne (pg_hba.conf με πιστοποίηση κωδικού).

4. Πιστοποίηση: HTTP Basic

Ο περιηγητής στέλνει τον χρήστη και τον κωδικό της PostgreSQL με κάθε αίτημα· το PgArachne ανοίγει σύνδεση ως αυτός ο χρήστης, ώστε όλα τα δικαιώματα της PostgreSQL (και το Row-Level Security) να ισχύουν απευθείας.

// Authorization header. TextEncoder makes non-ASCII passwords work.
function authHeader(user, pass) {
  const bytes = new TextEncoder().encode(user + ":" + pass);
  return "Basic " + btoa(String.fromCharCode(...bytes));
}
const base = location.origin + "/db/my_database";   // /{API_PREFIX}/{database}

Λάθος διαπιστευτήρια επιστρέφουν HTTP 401 με σφάλμα JSON· οι επαναλαμβανόμενες αποτυχίες περιορίζονται (429).

5. Endpoint 1 — JSON-RPC: κλήση συνάρτησης

Το POST /db/{database}/jsonrpc καλεί τη schema.function(jsonb). Η συνάρτηση δέχεται ένα όρισμα jsonb και επιστρέφει json.

PostgreSQL (στο setup.sql):

CREATE FUNCTION api.greet(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE sql AS $$
  SELECT json_build_object(
    'message', 'Hello, ' || COALESCE(params->>'name', 'world') || '!',
    'database_user', current_user,
    'server_time', now());
$$;
GRANT USAGE ON SCHEMA api TO webuser;
GRANT EXECUTE ON FUNCTION api.greet(jsonb) TO webuser;

Περιηγητής:

async function rpc(method, params) {
  const res = await fetch(base + "/jsonrpc", {
    method: "POST",
    headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", method, params, id: 1 }),
  });
  const body = await res.json();
  if (!res.ok || body.error) throw new Error(body.error.message);
  return body.result;
}

console.log(await rpc("api.greet", { name: "Alice" }));
// { message: "Hello, Alice!", database_user: "webuser", server_time: "..." }

Δοκιμή με curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"api.greet","params":{"name":"Alice"},"id":1}' \
  http://localhost:8080/db/my_database/jsonrpc

6. Endpoint 2 — SSE: λήψη μηνυμάτων σε πραγματικό χρόνο

Το GET /db/{database}/sse?channels=demo μεταδίδει τα μηνύματα NOTIFY της PostgreSQL ως Server-Sent Events. Οποιαδήποτε συνάρτηση μπορεί να δημοσιεύσει με pg_notify.

PostgreSQL:

CREATE FUNCTION api.send_message(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_notify('demo', json_build_object('from', current_user, 'text', params->>'text')::text);
  RETURN '{"sent": true}'::json;
END; $$;
GRANT EXECUTE ON FUNCTION api.send_message(jsonb) TO webuser;

Περιηγητής. Το ενσωματωμένο EventSource δεν μπορεί να στείλει κεφαλίδα Authorization, γι’ αυτό διαβάστε τη ροή με fetch():

async function listen(channels, onMessage, signal) {
  const res = await fetch(base + "/sse?channels=" + encodeURIComponent(channels), {
    headers: { "Authorization": authHeader(user, pass) }, signal,
  });
  if (!res.ok) throw new Error((await res.json()).error);
  const reader = res.body.getReader(), decoder = new TextDecoder();
  let buffer = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {      // an event ends with a blank line
      const event = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      for (const line of event.split("\n"))
        if (line.startsWith("data: ")) onMessage(JSON.parse(line.slice(6)));  // ":" lines are heartbeats
    }
  }
}

const controller = new AbortController();           // controller.abort() stops listening
listen("demo", (m) => console.log(m), controller.signal);
await rpc("api.send_message", { text: "Hello" });   // → { channel: "demo", data: { from: "webuser", text: "Hello" } }
Τα κανάλια δεν περιορίζονται ανά ρόλο: οποιοσδήποτε πιστοποιημένος χρήστης μπορεί να εγγραφεί σε οποιοδήποτε όνομα καναλιού. Μην κάνετε NOTIFY δεδομένα που δεν επιτρέπεται να βλέπουν όλοι οι χρήστες (λεπτομέρειες στις Ειδοποιήσεις σε Πραγματικό Χρόνο (SSE)).

Δοκιμή με curl: curl -N -u webuser:webuser_password "http://localhost:8080/db/my_database/sse?channels=demo", και μετά καλέστε το api.send_message από άλλο τερματικό.

7. Endpoint 3 — File: λήψη παραγόμενου αρχείου

Το POST /db/{database}/file επιστρέφει ακατέργαστα bytes (ή ZIP όταν η συνάρτηση επιστρέφει περισσότερα αρχεία) — χωρίς base64 μέσα σε JSON. Η συνάρτηση επιστρέφει γραμμές (path, content, mime_type, store_only).

PostgreSQL:

CREATE FUNCTION api.export_report(params jsonb DEFAULT '{}'::jsonb)
RETURNS TABLE (path text, content bytea, mime_type text, store_only boolean)
LANGUAGE sql AS $$
  SELECT 'report.csv', convert_to('id,name' || E'\n' || '1,Alice' || E'\n' || '2,Bob' || E'\n', 'UTF8'),
         'text/csv', false;
$$;
GRANT EXECUTE ON FUNCTION api.export_report(jsonb) TO webuser;

Επιστρέψτε περισσότερες γραμμές για να πάρετε αυτόματα ZIP. Δείτε τη Λήψη Αρχείων (/file) για όλες τις επιλογές.

Περιηγητής:

const res = await fetch(base + "/file", {
  method: "POST",
  headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
  body: JSON.stringify({ method: "api.export_report", params: {}, options: { filename: "report.csv" } }),
});
if (!res.ok) throw new Error((await res.json()).error.message);   // errors are JSON, never binary
const url = URL.createObjectURL(await res.blob());
const a = Object.assign(document.createElement("a"), { href: url, download: "report.csv" });
document.body.appendChild(a); a.click(); a.remove();
URL.revokeObjectURL(url);

Δοκιμή με curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"method":"api.export_report"}' http://localhost:8080/db/my_database/file -OJ

8. Συνδυάστε τα όλα

Αποθηκεύστε το index.html στον φάκελο STATIC_FILES_PATH και ανοίξτε το http://localhost:8080/. Περιέχει τα τρία παραπάνω αποσπάσματα συνδεδεμένα με κουμπιά (~100 γραμμές, χωρίς εξαρτήσεις). Εισαγάγετε το όνομα της βάσης δεδομένων, κρατήστε webuser / webuser_password και δοκιμάστε κάθε κουμπί: Call api.greet, Start listening και μετά Send, και Download report.csv.

9. Μετάβαση σε παραγωγή

  • HTTPS: τα διαπιστευτήρια Basic ταξιδεύουν με κάθε αίτημα — χρησιμοποιείτε πάντα TLS (βλ. Deployment & HTTPS) και αλλάξτε τον κωδικό του demo.
  • Κρατήστε τα διαπιστευτήρια μόνο στη μνήμη (σε μια μεταβλητή), όχι στο localStorage. Για συνεδρίες χωρίς επαναποστολή του κωδικού, ενεργοποιήστε το JWT_SECRET και χρησιμοποιήστε το get_jwt (βλ. Ασφάλεια & Πιστοποίηση).
  • Διαφορετική προέλευση για την ιστοσελίδα (π.χ. CDN ή άλλη θύρα): ορίστε ALLOWED_ORIGINS=https://app.example.com. Τα cross-origin αιτήματα αποκλείονται από προεπιλογή.
  • Ελάχιστα προνόμια: ένας ρόλος PostgreSQL ανά είδος χρήστη, EXECUTE μόνο στις συναρτήσεις που χρειάζονται, Row-Level Security για δεδομένα ανά χρήστη.
