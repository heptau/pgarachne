Tutorial passo a passo no navegador

A menor configuração funcional possível: um banco de dados PostgreSQL, o PgArachne e uma página HTML simples que faz login com autenticação HTTP Basic e usa três endpoints — JSON-RPC, SSE e download de arquivos. Sem framework e sem biblioteca JavaScript.

Baixe o exemplo pronto e acompanhe: setup.sql (banco de dados) e index.html (página web).

1. Pré-requisitos

  • Um servidor PostgreSQL em execução e o binário pgarachne (veja Instalação).
  • Um navegador moderno. Tudo abaixo funciona com o fetch() nativo — nada para baixar.

2. Preparar o banco de dados

O próprio PgArachne se conecta como uma role de serviço e carrega seu schema auxiliar. Crie ambos uma única vez:

createdb my_database
psql -d my_database -c "CREATE ROLE pgarachne LOGIN PASSWORD 'pgarachne_password'"
psql -d my_database -f sql/schema.sql       # PgArachne helper schema (from the repository)
psql -d my_database -f setup.sql            # the demo role and functions (download above)

setup.sql cria uma role de login webuser (a pessoa que usa a página web), um schema api e três funções. O funcionamento de cada uma é explicado nos passos 5–7.

As permissões são todo o modelo de segurança. Um usuário só pode chamar uma função se o PostgreSQL permitir: USAGE no schema e EXECUTE na função. Na demo, webuser recebe exatamente essas permissões em três funções — nada mais é acessível. O PostgreSQL concede EXECUTE em novas funções a todos por padrão; em projetos reais execute ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC e mantenha as funções expostas em um schema dedicado (veja Segurança e Autenticação).

3. Configurar e iniciar o PgArachne

Crie pgarachne.env ao lado do binário. STATIC_FILES_PATH faz o PgArachne servir também a página web, de modo que a página e a API compartilhem a mesma origem (sem necessidade de configurar CORS):

DB_HOST=localhost
DB_PORT=5432
DB_USER=pgarachne
DB_SSLMODE=disable                 # local, non-TLS PostgreSQL only
STATIC_FILES_PATH=/path/to/folder/with/index.html

A senha da role de serviço é lida pelo driver do PostgreSQL a partir de PGPASSWORD (ou ~/.pgpass). JWT_SECRET não é necessário — este tutorial usa somente autenticação Basic.

PGPASSWORD=pgarachne_password ./pgarachne

Abra http://localhost:8080/ depois de salvar index.html nessa pasta (passo 8). A role webuser precisa ter permissão para fazer login no PostgreSQL a partir do host do PgArachne (pg_hba.conf com autenticação por senha).

4. Autenticação: HTTP Basic

O navegador envia o usuário e a senha do PostgreSQL a cada requisição; o PgArachne abre uma conexão como esse usuário, de modo que todas as permissões do PostgreSQL (e a Row-Level Security) se aplicam diretamente.

// Authorization header. TextEncoder makes non-ASCII passwords work.
function authHeader(user, pass) {
  const bytes = new TextEncoder().encode(user + ":" + pass);
  return "Basic " + btoa(String.fromCharCode(...bytes));
}
const base = location.origin + "/db/my_database";   // /{API_PREFIX}/{database}

Credenciais incorretas retornam HTTP 401 com um erro JSON; falhas repetidas sofrem limitação de taxa (429).

5. Endpoint 1 — JSON-RPC: chamar uma função

POST /db/{database}/jsonrpc chama schema.function(jsonb). A função recebe um único argumento jsonb e retorna json.

PostgreSQL (em setup.sql):

CREATE FUNCTION api.greet(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE sql AS $$
  SELECT json_build_object(
    'message', 'Hello, ' || COALESCE(params->>'name', 'world') || '!',
    'database_user', current_user,
    'server_time', now());
$$;
GRANT USAGE ON SCHEMA api TO webuser;
GRANT EXECUTE ON FUNCTION api.greet(jsonb) TO webuser;

Navegador:

async function rpc(method, params) {
  const res = await fetch(base + "/jsonrpc", {
    method: "POST",
    headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", method, params, id: 1 }),
  });
  const body = await res.json();
  if (!res.ok || body.error) throw new Error(body.error.message);
  return body.result;
}

console.log(await rpc("api.greet", { name: "Alice" }));
// { message: "Hello, Alice!", database_user: "webuser", server_time: "..." }

Teste com curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"api.greet","params":{"name":"Alice"},"id":1}' \
  http://localhost:8080/db/my_database/jsonrpc

6. Endpoint 2 — SSE: receber mensagens em tempo real

GET /db/{database}/sse?channels=demo transmite as mensagens NOTIFY do PostgreSQL como Server-Sent Events. Qualquer função pode publicar com pg_notify.

PostgreSQL:

CREATE FUNCTION api.send_message(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_notify('demo', json_build_object('from', current_user, 'text', params->>'text')::text);
  RETURN '{"sent": true}'::json;
END; $$;
GRANT EXECUTE ON FUNCTION api.send_message(jsonb) TO webuser;

Navegador. O EventSource nativo não consegue enviar um header Authorization, então leia o stream com fetch():

async function listen(channels, onMessage, signal) {
  const res = await fetch(base + "/sse?channels=" + encodeURIComponent(channels), {
    headers: { "Authorization": authHeader(user, pass) }, signal,
  });
  if (!res.ok) throw new Error((await res.json()).error);
  const reader = res.body.getReader(), decoder = new TextDecoder();
  let buffer = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {      // an event ends with a blank line
      const event = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      for (const line of event.split("\n"))
        if (line.startsWith("data: ")) onMessage(JSON.parse(line.slice(6)));  // ":" lines are heartbeats
    }
  }
}

const controller = new AbortController();           // controller.abort() stops listening
listen("demo", (m) => console.log(m), controller.signal);
await rpc("api.send_message", { text: "Hello" });   // → { channel: "demo", data: { from: "webuser", text: "Hello" } }
Os canais não são limitados por role: qualquer usuário autenticado pode assinar qualquer nome de canal. Não envie com NOTIFY dados que nem todos os usuários podem ver (detalhes em Notificações em tempo real).

Teste com curl: curl -N -u webuser:webuser_password "http://localhost:8080/db/my_database/sse?channels=demo", depois chame api.send_message em outro terminal.

7. Endpoint 3 — File: baixar um arquivo gerado

POST /db/{database}/file retorna bytes brutos (ou um ZIP quando a função retorna vários arquivos) — sem base64 em JSON. A função retorna linhas (path, content, mime_type, store_only).

PostgreSQL:

CREATE FUNCTION api.export_report(params jsonb DEFAULT '{}'::jsonb)
RETURNS TABLE (path text, content bytea, mime_type text, store_only boolean)
LANGUAGE sql AS $$
  SELECT 'report.csv', convert_to('id,name' || E'\n' || '1,Alice' || E'\n' || '2,Bob' || E'\n', 'UTF8'),
         'text/csv', false;
$$;
GRANT EXECUTE ON FUNCTION api.export_report(jsonb) TO webuser;

Retorne mais linhas para obter um ZIP automaticamente. Veja Download de arquivos para todas as opções.

Navegador:

const res = await fetch(base + "/file", {
  method: "POST",
  headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
  body: JSON.stringify({ method: "api.export_report", params: {}, options: { filename: "report.csv" } }),
});
if (!res.ok) throw new Error((await res.json()).error.message);   // errors are JSON, never binary
const url = URL.createObjectURL(await res.blob());
const a = Object.assign(document.createElement("a"), { href: url, download: "report.csv" });
document.body.appendChild(a); a.click(); a.remove();
URL.revokeObjectURL(url);

Teste com curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"method":"api.export_report"}' http://localhost:8080/db/my_database/file -OJ

8. Juntando tudo

Salve index.html na pasta STATIC_FILES_PATH e abra http://localhost:8080/. Ele contém os três trechos acima ligados a botões (~100 linhas, sem dependências). Informe o nome do banco de dados, mantenha webuser / webuser_password e experimente cada botão: Call api.greet, Start listening e depois Send, e Download report.csv.

9. Indo para produção

  • HTTPS: as credenciais Basic viajam a cada requisição — use sempre TLS (veja Deployment e HTTPS) e altere a senha da demo.
  • Mantenha as credenciais apenas em memória (uma variável), não em localStorage. Para sessões sem reenviar a senha, habilite JWT_SECRET e use get_jwt (veja Segurança e Autenticação).
  • Origem diferente para a página web (por exemplo, uma CDN ou outra porta): defina ALLOWED_ORIGINS=https://app.example.com. Requisições cross-origin são bloqueadas por padrão.
  • Privilégio mínimo: uma role do PostgreSQL por tipo de usuário, EXECUTE apenas nas funções de que precisam, Row-Level Security para dados por usuário.
