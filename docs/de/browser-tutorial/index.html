Schritt-für-Schritt-Tutorial für den Browser

Die kleinstmögliche funktionierende Konfiguration: eine PostgreSQL-Datenbank, PgArachne und eine einzige einfache HTML-Seite, die sich per HTTP-Basic-Authentifizierung anmeldet und drei Endpunkte nutzt — JSON-RPC, SSE und Datei-Download. Kein Framework und keine JavaScript-Bibliothek.

Laden Sie das fertige Beispiel herunter und folgen Sie der Anleitung: setup.sql (Datenbank) und index.html (Webseite).

1. Voraussetzungen

  • Ein laufender PostgreSQL-Server und die pgarachne-Binärdatei (siehe Installation).
  • Ein moderner Browser. Alles Folgende funktioniert mit dem eingebauten fetch() — es muss nichts heruntergeladen werden.

2. Datenbank vorbereiten

PgArachne selbst verbindet sich als Service-Rolle und lädt sein Hilfsschema. Legen Sie beides einmalig an:

createdb my_database
psql -d my_database -c "CREATE ROLE pgarachne LOGIN PASSWORD 'pgarachne_password'"
psql -d my_database -f sql/schema.sql       # PgArachne helper schema (from the repository)
psql -d my_database -f setup.sql            # the demo role and functions (download above)

setup.sql erstellt eine Login-Rolle webuser (die Person, die die Webseite nutzt), ein Schema api und drei Funktionen. Wie jede einzelne funktioniert, wird in den Schritten 5–7 erklärt.

Berechtigungen sind das gesamte Sicherheitsmodell. Ein Benutzer kann eine Funktion nur aufrufen, wenn PostgreSQL es erlaubt: USAGE auf dem Schema und EXECUTE auf der Funktion. In der Demo erhält webuser genau diese Rechte für drei Funktionen — sonst ist nichts erreichbar. PostgreSQL gewährt EXECUTE auf neue Funktionen standardmäßig jedem; führen Sie in echten Projekten ALTER DEFAULT PRIVILEGES REVOKE EXECUTE ON FUNCTIONS FROM PUBLIC aus und legen Sie freigegebene Funktionen in einem eigenen Schema ab (siehe Sicherheit & Authentifizierung).

3. PgArachne konfigurieren und starten

Erstellen Sie pgarachne.env neben der Binärdatei. Mit STATIC_FILES_PATH liefert PgArachne auch die Webseite aus, sodass Seite und API denselben Origin teilen (keine CORS-Konfiguration nötig):

DB_HOST=localhost
DB_PORT=5432
DB_USER=pgarachne
DB_SSLMODE=disable                 # local, non-TLS PostgreSQL only
STATIC_FILES_PATH=/path/to/folder/with/index.html

Das Passwort der Service-Rolle liest der PostgreSQL-Treiber aus PGPASSWORD (oder ~/.pgpass). JWT_SECRET wird nicht benötigt — dieses Tutorial verwendet ausschließlich Basic-Authentifizierung.

PGPASSWORD=pgarachne_password ./pgarachne

Öffnen Sie http://localhost:8080/, nachdem Sie index.html in diesem Ordner gespeichert haben (Schritt 8). Die Rolle webuser muss sich vom PgArachne-Host aus bei PostgreSQL anmelden dürfen (pg_hba.conf mit Passwort-Authentifizierung).

4. Authentifizierung: HTTP Basic

Der Browser sendet bei jeder Anfrage PostgreSQL-Benutzer und -Passwort; PgArachne öffnet eine Verbindung als dieser Benutzer, sodass alle PostgreSQL-Berechtigungen (und Row-Level Security) direkt gelten.

// Authorization header. TextEncoder makes non-ASCII passwords work.
function authHeader(user, pass) {
  const bytes = new TextEncoder().encode(user + ":" + pass);
  return "Basic " + btoa(String.fromCharCode(...bytes));
}
const base = location.origin + "/db/my_database";   // /{API_PREFIX}/{database}

Falsche Zugangsdaten liefern HTTP 401 mit einem JSON-Fehler; wiederholte Fehlversuche werden ratenbegrenzt (429).

5. Endpunkt 1 — JSON-RPC: eine Funktion aufrufen

POST /db/{database}/jsonrpc ruft schema.function(jsonb) auf. Die Funktion nimmt ein jsonb-Argument entgegen und gibt json zurück.

PostgreSQL (in setup.sql):

CREATE FUNCTION api.greet(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE sql AS $$
  SELECT json_build_object(
    'message', 'Hello, ' || COALESCE(params->>'name', 'world') || '!',
    'database_user', current_user,
    'server_time', now());
$$;
GRANT USAGE ON SCHEMA api TO webuser;
GRANT EXECUTE ON FUNCTION api.greet(jsonb) TO webuser;

Browser:

async function rpc(method, params) {
  const res = await fetch(base + "/jsonrpc", {
    method: "POST",
    headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
    body: JSON.stringify({ jsonrpc: "2.0", method, params, id: 1 }),
  });
  const body = await res.json();
  if (!res.ok || body.error) throw new Error(body.error.message);
  return body.result;
}

console.log(await rpc("api.greet", { name: "Alice" }));
// { message: "Hello, Alice!", database_user: "webuser", server_time: "..." }

Test mit curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"api.greet","params":{"name":"Alice"},"id":1}' \
  http://localhost:8080/db/my_database/jsonrpc

6. Endpunkt 2 — SSE: Echtzeit-Nachrichten empfangen

GET /db/{database}/sse?channels=demo streamt PostgreSQL-NOTIFY-Nachrichten als Server-Sent Events. Jede Funktion kann mit pg_notify veröffentlichen.

PostgreSQL:

CREATE FUNCTION api.send_message(params jsonb DEFAULT '{}'::jsonb) RETURNS json
LANGUAGE plpgsql AS $$
BEGIN
  PERFORM pg_notify('demo', json_build_object('from', current_user, 'text', params->>'text')::text);
  RETURN '{"sent": true}'::json;
END; $$;
GRANT EXECUTE ON FUNCTION api.send_message(jsonb) TO webuser;

Browser. Das eingebaute EventSource kann keinen Authorization-Header senden, daher lesen Sie den Stream mit fetch():

async function listen(channels, onMessage, signal) {
  const res = await fetch(base + "/sse?channels=" + encodeURIComponent(channels), {
    headers: { "Authorization": authHeader(user, pass) }, signal,
  });
  if (!res.ok) throw new Error((await res.json()).error);
  const reader = res.body.getReader(), decoder = new TextDecoder();
  let buffer = "";
  for (;;) {
    const { done, value } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    let end;
    while ((end = buffer.indexOf("\n\n")) >= 0) {      // an event ends with a blank line
      const event = buffer.slice(0, end);
      buffer = buffer.slice(end + 2);
      for (const line of event.split("\n"))
        if (line.startsWith("data: ")) onMessage(JSON.parse(line.slice(6)));  // ":" lines are heartbeats
    }
  }
}

const controller = new AbortController();           // controller.abort() stops listening
listen("demo", (m) => console.log(m), controller.signal);
await rpc("api.send_message", { text: "Hello" });   // → { channel: "demo", data: { from: "webuser", text: "Hello" } }
Kanäle sind nicht rollenbezogen: Jeder authentifizierte Benutzer kann jeden Kanalnamen abonnieren. Senden Sie per NOTIFY keine Daten, die nicht jeder Benutzer sehen darf (Details unter Realtime-Benachrichtigungen (SSE)).

Test mit curl: curl -N -u webuser:webuser_password "http://localhost:8080/db/my_database/sse?channels=demo", rufen Sie dann api.send_message aus einem anderen Terminal auf.

7. Endpunkt 3 — Datei: eine generierte Datei herunterladen

POST /db/{database}/file liefert rohe Bytes (oder ein ZIP, wenn die Funktion mehrere Dateien zurückgibt) — kein Base64 in JSON. Die Funktion gibt Zeilen (path, content, mime_type, store_only) zurück.

PostgreSQL:

CREATE FUNCTION api.export_report(params jsonb DEFAULT '{}'::jsonb)
RETURNS TABLE (path text, content bytea, mime_type text, store_only boolean)
LANGUAGE sql AS $$
  SELECT 'report.csv', convert_to('id,name' || E'\n' || '1,Alice' || E'\n' || '2,Bob' || E'\n', 'UTF8'),
         'text/csv', false;
$$;
GRANT EXECUTE ON FUNCTION api.export_report(jsonb) TO webuser;

Geben Sie mehr Zeilen zurück, um automatisch ein ZIP zu erhalten. Alle Optionen finden Sie unter Datei-Download (/file).

Browser:

const res = await fetch(base + "/file", {
  method: "POST",
  headers: { "Authorization": authHeader(user, pass), "Content-Type": "application/json" },
  body: JSON.stringify({ method: "api.export_report", params: {}, options: { filename: "report.csv" } }),
});
if (!res.ok) throw new Error((await res.json()).error.message);   // errors are JSON, never binary
const url = URL.createObjectURL(await res.blob());
const a = Object.assign(document.createElement("a"), { href: url, download: "report.csv" });
document.body.appendChild(a); a.click(); a.remove();
URL.revokeObjectURL(url);

Test mit curl:

curl -u webuser:webuser_password -H "Content-Type: application/json" \
  -d '{"method":"api.export_report"}' http://localhost:8080/db/my_database/file -OJ

8. Alles zusammensetzen

Speichern Sie index.html im Ordner STATIC_FILES_PATH und öffnen Sie http://localhost:8080/. Die Datei enthält die drei obigen Snippets, verbunden mit Schaltflächen (~100 Zeilen, keine Abhängigkeiten). Geben Sie den Datenbanknamen ein, behalten Sie webuser / webuser_password bei und probieren Sie jede Schaltfläche aus: Call api.greet, Start listening und dann Send sowie Download report.csv.

9. Der Weg in die Produktion

  • HTTPS: Basic-Zugangsdaten werden bei jeder Anfrage mitgesendet — verwenden Sie immer TLS (siehe Bereitstellung & HTTPS) und ändern Sie das Demo-Passwort.
  • Zugangsdaten nur im Speicher halten (in einer Variable), nicht in localStorage. Für Sitzungen ohne erneutes Senden des Passworts aktivieren Sie JWT_SECRET und verwenden get_jwt (siehe Sicherheit & Authentifizierung).
  • Anderer Origin für die Webseite (z. B. ein CDN oder ein anderer Port): Setzen Sie ALLOWED_ORIGINS=https://app.example.com. Cross-Origin-Anfragen sind standardmäßig blockiert.
  • Minimale Rechte: eine PostgreSQL-Rolle pro Benutzerart, EXECUTE nur auf den benötigten Funktionen, Row-Level Security für benutzerspezifische Daten.
